### DEC-005 — 세션: DB 세션 + Redis 캐시 (JWT 아님)

> **상태: 폐기 (`DEC-030` 으로 대체).**
> **요구(«DB 세션 + 즉시 반영»)는 옳았고 그대로 유지합니다.** 폐기한 것은 **수단**입니다 —
> Auth.js 는 Credentials Provider(`DEC-002`)를 쓰면 세션 전략이 **JWT로 고정**되어
> database 세션을 쓸 수 없습니다. 두 결정이 서로를 무효화하고 있었습니다.

| 항목 | 내용 |
| --- | --- |
| **결정** | Auth.js 의 database 세션 전략을 쓰고, 조회 부하만 Redis로 캐시한다 |
| **검토안** | ① DB 세션 ② JWT 세션 |
| **근거** | 승인·정지·역할 변경을 **즉시 반영**해야 한다. JWT는 발급 후 서버가 취소할 수 없다 |
| **영향** | 요청마다 세션 조회가 필요하다 → Redis 캐시(15분)로 완화. 사용자별 세션 인덱스를 Redis Set으로 관리해 강제 로그아웃을 구현한다 |
| **결정일** | 2026-08-28 |

| **리다이렉트 루프** | proxy 를 «쿠키 있으면 `/login` → `/dashboard`» 로 짜면, 세션이 지워진 사용자가 **무한 루프**에 빠진다(proxy: 쿠키 있음 → 대시보드, DAL: 세션 무효 → 로그인). 서버 컴포넌트 렌더 중에는 쿠키를 지울 수 없어 DAL 이 죽은 쿠키를 치울 수도 없다. **proxy 는 «로그인 쪽으로»만 보낸다. 단방향이다** |
| **proxy 의 import** | 쿠키 이름 상수 하나뿐. `lib/env.ts` 는 `server-only` 라 proxy 그래프에 들어가면 안 된다 |
| **쿠키 속성** | `httpOnly` · `sameSite: "lax"` · `secure: COOKIE_SECURE` · `path: "/"` · **`domain` 없음**. 「로그인 상태 유지」 체크 시에만 `maxAge`, 미체크면 **넣지 않아 브라우저 세션 쿠키**로 (`REQ-02 · 2.7`) |
| **슬라이딩 만료** | 쿠키 재발급으로 하면 렌더 중 `cookies().set()` 이라 터진다. **정본은 `sessions.expires` 이고 이걸 갱신**한다. `last_seen_at` 은 **5분 이상 지났을 때만** 쓴다 |
| **무효화 순서** | ① DB 트랜잭션(`users.status` + `sessions` 삭제) **커밋** → ② Redis 삭제. **뒤집으면 커밋 전 요청이 캐시를 되살린다.** `user:sessions:{userId}` Set 의 원소는 세션 `id` 가 아니라 **`tokenHash`** 여야 한다 — `id` 를 넣으면 `sess:{tokenHash}` 를 지울 수 없다 |
| **DAL** | `getSession()` 은 React `cache()` 로 감싸 한 렌더 패스에 한 번만 조회. 반환은 **DTO** 로 좁히고 `passwordHash` 를 절대 싣지 않는다 |
| **세션 재발급** | 로그인 성공 직후 **요청에 딸려온 기존 세션 행을 지우고** 새로 발급(세션 고정 방지). 비밀번호 변경 시 **본인의 다른 세션**을 전부 지운다 |
| **`?next=`** | `/` 로 시작하고 `//`·`/\` 로 시작하지 않는 값만 허용. 그 외에는 `/dashboard` (`NFR-SEC-011`) |
| **Server Action Origin** | Next.js 는 Server Action 의 `Origin` 과 `Host` 를 비교해 다르면 중단한다. **팀 개방(`DEC-023`) 시 `http://<PC IP>:3100` 으로 붙으면 로그인 폼이 통째로 실패**한다 → `next.config.ts` 의 `serverActions.allowedOrigins` 에 PC IP 를 넣는다 |

## 1.3 의도적으로 하지 않기로 한 것

지금 단계에서 **일부러 넣지 않은** 것들입니다. 나중에 "왜 없지?"라는 질문이 나올 때의 답입니다.

| 항목 | 하지 않는 이유 |
| --- | --- |
| 마이크로서비스 분리 | 동시 20명 규모다. 단일 앱 + 워커로 충분하고 운영 부담만 커진다 |
| 관리자 화면에서 콘텐츠 타입 스키마 직접 정의 | 타입 안정성과 마이그레이션 추적을 잃는다. 스키마는 코드, 운영 설정만 DB |
| 자료 승인 워크플로 | 팀 내부용이다. 등록 즉시 게시하고, 문제가 있으면 EDITOR가 정리한다 |
| 댓글·토론 기능 | 사내 메신저가 이미 있다. 필요해지면 자료별 메모로 시작한다 |
| 실시간 협업 편집 | 요구가 없다 |
| 전문 검색 엔진 | 규모에 비해 과하다 (`DEC-007`) |
| 다국어 UI | 사내 한국어 사용자만 쓴다. 문자열은 분리해 두어 확장만 열어 둔다 |
| GraphQL | 화면과 API를 같은 팀이 만든다. Server Action으로 충분하다 |
| 자체 파일 뷰어 | 브라우저 기본 동작과 다운로드로 충분하다 |
| 오브젝트 스토리지(MinIO/S3) | 1단계 규모에 과하다 (`DEC-019`). 드라이버 인터페이스만 남겨 두었다 |
| RSS·뉴스레터 자동 수집 | 아무도 고르지 않은 자료가 쌓인다. 수집 판단은 사람이 CLI에서 한다 (`DEC-025`) |
| **자료 검수** | 누군가 비워야 하는 목록은 비워지지 않는다. 품질은 등록 시점에 건다 (`DEC-029`) |
| **인증 라이브러리(Auth.js)** | 소셜·SSO를 안 쓰므로 얻는 것이 없고, Credentials 를 쓰면 DB 세션이 막힌다 (`DEC-030`) |
| GitHub 자료 자동 아카이브 | 개발 PC 디스크가 순식간에 찬다. 선택 실행 + 총량 100GB (`DEC-022`) |

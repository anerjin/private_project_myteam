### DEC-014 — 로그인 식별자: 아이디 + 비밀번호 (이메일 미사용)

| 항목 | 내용 |
| --- | --- |

| **아이디 규칙** | 영문 소문자·숫자·`_`·`.` 4~20자. 대소문자 구분 없이 유일. 변경 불가 |

| **영향** | 이메일 인증(`FR-AUTH-005`)과 메일 기반 비밀번호 재설정(`FR-AUTH-010`)을 **제거**한다. 비밀번호를 잊으면 **관리자가 초기화**한다(`FR-ADM-007`). 가입 도메인 화이트리스트(`FR-AUTH-003`)도 제거한다. 감사 로그의 행위자 스냅샷은 `actor_username` 이다 |
| **대체** | `DEC-002` 의 식별자 부분을 개정한다 |
| **결정일** | 2026-08-28 |

### DEC-015 — 알림: 인앱 알림만 (메일·메신저 연동 없음)

| **해소** | `OPEN-003`(메일 발송 수단) · `OPEN-012`(사내 메신저 연동) |

## 1.3 의도적으로 하지 않기로 한 것

지금 단계에서 **일부러 넣지 않은** 것들입니다. 나중에 "왜 없지?"라는 질문이 나올 때의 답입니다.

| 항목 | 하지 않는 이유 |
| --- | --- |
| 마이크로서비스 분리 | 동시 20명 규모다. 단일 앱 + 워커로 충분하고 운영 부담만 커진다 |
| 관리자 화면에서 콘텐츠 타입 스키마 직접 정의 | 타입 안정성과 마이그레이션 추적을 잃는다. 스키마는 코드, 운영 설정만 DB |
| 자료 승인 워크플로 | 팀 내부용이다. 등록 즉시 게시하고, 문제가 있으면 EDITOR가 정리한다 |
| 댓글·토론 기능 | 사내 메신저가 이미 있다. 필요해지면 자료별 메모로 시작한다 |
| 실시간 협업 편집 | 요구가 없다 |
| 전문 검색 엔진 | 규모에 비해 과하다 (`DEC-007`) |
| 다국어 UI | 사내 한국어 사용자만 쓴다. 문자열은 분리해 두어 확장만 열어 둔다 |
| GraphQL | 화면과 API를 같은 팀이 만든다. Server Action으로 충분하다 |
| 자체 파일 뷰어 | 브라우저 기본 동작과 다운로드로 충분하다 |
| 오브젝트 스토리지(MinIO/S3) | 1단계 규모에 과하다 (`DEC-019`). 드라이버 인터페이스만 남겨 두었다 |

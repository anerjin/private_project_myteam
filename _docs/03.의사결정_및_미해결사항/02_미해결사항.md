| **OPEN-019** | **`npm run e2e` 가 이미 빨갛다 — 17건 중 10건 실패** | `DEC-074` 이식을 확인하다 드러났습니다. **이식과 무관한 기존 결함**이고, `P9` 가 「e2e 6종 통과」로 닫힌 뒤 어느 시점엔가 깨진 채 아무도 안 돌려 봤습니다(`[069]` 에서 처음 실측). 증상은 서버 액션 왕복 한 번에 **탭이 통째로 죽는 것**입니다 — `page.waitForLoadState: Navigation failed because page crashed!`. 기존 「할 일 지우기」 단추로도 재현됩니다. **실측(2026-09-08)**: 현재 설정 **10 실패 / 7 통과**, `channel: "chromium"` 을 주면 **5 실패 / 12 통과**. 종료 코드는 둘 다 `1` 이라 CI 게이트는 정상으로 막힙니다. **채널 교체가 절반만 고칩니다** — `a11y` 의 「로그인 뒤 주요 화면」 둘은 채널을 바꿔도 같은 자리에서 죽습니다. 그래서 「한 줄 고치면 된다」가 아닙니다. ① 채널을 바꿔 5건으로 줄이고 나머지를 따로 파거나 ② 크래시 원인(로그인 뒤 첫 화면)을 먼저 잡아야 합니다 | **`P10` E2E 착수 전.** 다만 지금도 `npm run e2e` 는 실패하므로, 그것을 게이트로 쓰는 순간 막힙니다 |

## 2.3 해결 절차

```mermaid
flowchart LR
    A["OPEN 등록<br/>담당·시점 지정"] --> B["담당자가 근거 정리"]
    B --> C["팀 합의"]
    C --> D["DCS-01 에 DEC-0NN 로 등록"]
    D --> E["2.2 해결된 항목으로 이동"]
    E --> F["참조하던 문서 갱신 + 메모리 기록"]
```

1. 담당자가 결정 근거를 정리해 팀에 공유한다
2. 결정되면 [DCS-01 의사결정 기록](01_의사결정_기록.md)에 `DEC-0NN` 으로 등록한다
3. 이 문서의 **2.1 열린 항목에서 제거**하고 **2.2 해결된 항목**에 한 줄 남긴다
4. 그 `OPEN` ID를 참조하던 문서를 새 `DEC` ID로 갱신한다
5. 작업 내용을 `_docs/99.memory/memory_NN.md` 에 기록한다

## 2.4 지켜볼 위험

결정은 끝났지만 **운영하면서 문제가 드러날 수 있는** 지점입니다.
실제로 문제가 되면 `OPEN-022` 부터 등록해 다시 결정합니다.

| 지점 | 우려 | 지켜볼 신호 |
| --- | --- | --- |
| **백업이 같은 PC에 있다** (`DEC-024`) | PC 고장·디스크 전체 장애·랜섬웨어에 **원본과 백업이 함께 사라진다.** 이 시스템에서 가장 큰 단일 위험이다 | 자료가 100건을 넘거나 팀이 실제로 쓰기 시작하면 즉시 외부 매체로 전환한다 |
| 개발 PC가 곧 서버 (`DEC-013`) | PC를 끄면 서비스와 MCP 수집이 함께 멈춘다 | M5 팀 개방(`DEC-023`) 후 불편이 반복되면 2단계 이관 |
| 관리자 비밀번호 분실 | 메일이 없어 **시드 스크립트가 유일한 복구 경로**다. 관리자가 1명이면 더 위험 | M1에 복구 절차를 운영 문서로 남긴다. 관리자를 2명 두면 완화된다 |
| 승인 알림 전달 | 인앱 알림만 있어 승인 여부를 사용자가 **직접 확인**해야 한다 | M5 개방 후 "승인됐는지 모르겠다"는 문의가 반복되는지 |
| **에이전트 등록분 품질** (`DEC-029`) | 검수를 폐기해 **`neowave-work-collect` Skill 의 품질 규칙이 유일한 방어선**이 됐다. 규칙이 느슨하면 걸러지지 않은 자료가 그대로 쌓인다 | 요약이 원문과 어긋나거나 `applicability` 가 형식적인 자료가 눈에 띄는지. 그러면 검수를 되살리는 게 아니라 **Skill 규칙을 조인다** |
| 아카이브 100GB 상한 (`DEC-022`) | 상한에 닿았을 때 **무엇을 지울지** 기준이 없다 | 80GB 경고가 뜨는 시점에 정리 기준을 정한다 |
| 계정 익명화 (`DEC-021`) | 자료·감사 로그 참조를 지키려고 물리 삭제 대신 익명화한다. 개인정보 관점에서 충분한지 확인 필요 | 사내 개인정보 정책이 정해지면 대조한다 |
| 소프트 삭제 + URL 유니크 | 삭제된 자료와 같은 URL을 다시 등록할 수 있고, 복구 시 충돌한다 | 복구 로직에서 처리. M2 구현 시 테스트 |
| 태그 자유 생성 | CLI 수집이 늘면 유사 태그가 빠르게 늘어난다 | 태그 수가 자료 수를 앞지르는지 |
| **`EDITOR` 역할의 실효성** | 팀이 작으면 `MEMBER`·`ADMIN` 만으로 충분할 수 있다. **검수 해제라는 근거가 `DEC-029` 로 사라져 존재 이유가 하나 줄었다** | 남은 근거는 «모든 자료 수정 · 분류 정리 · 아카이브 실행» 셋. `EDITOR` 를 실제로 임명하는 사람이 나오는지 |

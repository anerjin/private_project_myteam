## 1. 기동 · 정지

```powershell
cd E:\github\doi_dev_team\project

# 컨테이너 (PostgreSQL · Redis)
docker compose -f ..\docker\docker-compose.dev.yml up -d
docker compose -f ..\docker\docker-compose.dev.yml down

# 앱
npm run dev            # 개발 (http://localhost:3100)
npm run build; npm start   # 운영
```

**순서가 있습니다** — 컨테이너가 먼저입니다. 앱이 먼저 뜨면 DB 연결에 실패하고,
그 오류는 「처리 중 문제가 발생했습니다」로만 보입니다.

살아 있는지는 `http://localhost:3100/api/health` 가 답합니다 (DB·Redis·디스크·스토리지 4항목).

## 2. 매일 도는 것 — 작업 스케줄러에 등록

두 가지를 Windows 작업 스케줄러에 넣습니다. **아직 등록하지 않았다면 지금 하십시오.**

```powershell
# 관리자 PowerShell
$dir = "E:\github\doi_dev_team\project"

# ① 백업 — 매일 03:00 (NFR-BACKUP-001)
Register-ScheduledTask -TaskName "QueenBee 백업" `
  -Action (New-ScheduledTaskAction -Execute "npm.cmd" -Argument "run backup" -WorkingDirectory $dir) `
  -Trigger (New-ScheduledTaskTrigger -Daily -At 3am)

# ② 유지보수 — 매일 04:00 (DEC-060)
Register-ScheduledTask -TaskName "QueenBee 유지보수" `
  -Action (New-ScheduledTaskAction -Execute "npm.cmd" -Argument "run maintenance" -WorkingDirectory $dir) `
  -Trigger (New-ScheduledTaskTrigger -Daily -At 4am)
```

**유지보수가 하는 일**: 저장소 메타 갱신(주 1회) · 원본 링크 확인(월 1회) ·
휴지통 정리(30일 지난 것) · 탈퇴 계정 익명화(1년) · 감사 로그 정리(1년).
밀린 것만 돌리므로 매일 불러도 됩니다.

**등록했는지 확인하려면** 관리자 화면의 「작업」에서 각 스케줄의 「마지막 실행」을
보십시오. `아직 안 돎` 이 계속 남아 있으면 스케줄러가 안 도는 것입니다.
「지금 실행」 버튼이 같은 함수를 부르므로, 눌러서 되는지 먼저 확인할 수 있습니다.

## 3. 백업

```powershell
npm run backup
```

| 무엇 | 어디 | 주기 |
| --- | --- | --- |
| DB (`pg_dump -Fc`) | `C:\queenbee-backup\db\` | 매일 03:00 |
| 파일 (`STORAGE_ROOT` 전체) | `C:\queenbee-backup\files\` | 백업할 때마다 |

보관: **일 7개 + 주 4개 + 월 6개** (`NFR-BACKUP-002`). 그 밖은 자동으로 지웁니다.

받은 뒤 **`pg_restore --list` 로 열어 봅니다** — 0바이트나 잘린 파일이 매일
쌓이는 것을 막는 유일한 방법입니다. 못 읽으면 백업이 실패로 끝납니다.

> **⚠ 백업이 같은 PC 에 있습니다** (`DEC-024`).
> PC 고장·디스크 장애·랜섬웨어에는 **원본과 백업이 함께 사라집니다.**
> 이 위험을 알고 고른 것이고, 완화책은 아래 리허설 때 외부 매체로 1부
> 복사하는 것입니다. 2단계 이관 시 분리 보관으로 바꿉니다.

백업 위치를 바꾸려면 환경변수 `BACKUP_ROOT` 를 주십시오.

## 4. 복구 리허설 — 분기 1회 (`NFR-BACKUP-005`)

```powershell
npm run restore
```

**실제 DB 를 건드리지 않습니다.** 임시 데이터베이스에 최신 백업을 넣어 보고,
세어 보고, 지웁니다. 이렇게 나오면 통과입니다:

```
  들어온 것
    테이블 28 · 계정 1 · 자료 1 · 카테고리 27

✓ 리허설 통과 — 이 백업으로 복구할 수 있습니다.
```

**무엇을 확인하는가**: 덤프가 읽히는가 · 스키마가 서는가 · 행이 들어오는가 ·
**활성 관리자가 있는가**. 마지막이 중요합니다 — 데이터가 다 돌아와도 아무도
못 들어가면 복구가 아닙니다.

리허설이 끝나면 **백업본을 USB 나 외장 디스크로 1부 복사**하십시오 (`DEC-024` 완화책).

## 5. 실제로 복구해야 할 때

> **먼저 지금 상태를 받아 두십시오.** 복구하려던 백업이 잘못된 것일 수 있고,
> 그때 돌아올 자리가 필요합니다.

```powershell
npm run backup                    # ① 지금 것을 먼저
npm run restore                   # ② 리허설로 백업이 멀쩡한지 확인
npm run restore -- --into-live    # ③ 실제 DB 를 덮어쓴다

# ④ 파일도 되돌린다
robocopy "C:\queenbee-backup\files" "E:\queenbee-data\files" /MIR
```

특정 시점으로 돌아가려면 `-- --file queenbee-2026-08-30-0300.dump` 처럼 지정합니다.
`C:\queenbee-backup\db\` 에 있는 이름을 그대로 씁니다.

**DB 만 되돌리면 안 됩니다** — 첨부와 아카이브가 없는 자료가 됩니다. ④를 빠뜨리지 마십시오.

목표: **RPO 24시간 · RTO 4시간** (`NFR-BACKUP-004`). 즉 마지막 백업 이후의 등록은
사라지고, 4시간 안에 서비스를 되살립니다.

## 6. 최고관리자 계정

| 항목 | 값 |
| --- | --- |
| 아이디 | `master` |
| 이름 · 역할 | 관리자 · `ADMIN` |
| 최초 로그인 변경 강제 | **없음** |

비밀번호를 바꾸려면 **마이페이지 > 비밀번호 변경**입니다. 화면의 규칙은
**10자 이상 · 영문·숫자·특수문자 중 2종 이상**입니다 (`REQ-02 · 2.9`).

> **지금 쓰는 비밀번호는 7자라 그 규칙을 통과하지 못합니다.** 운영자가 그 값을
> 고른 것이고 로그인에는 지장이 없지만(로그인은 길이를 보지 않습니다), **한 번
> 바꾸면 같은 값으로 되돌릴 수 없습니다.** 바꿀 때는 10자 이상으로 정하십시오.

### 비밀번호를 잊었을 때

**관리자가 둘 이상이면** — 다른 관리자가 관리자 → 회원 → 해당 회원의 「비밀번호
초기화」를 누릅니다. 임시 비밀번호가 나오고, 받은 사람은 첫 로그인에서 바꿉니다.

**관리자가 하나뿐이고 그 계정이 잠겼으면** — 화면으로는 방법이 없습니다.
DB 를 직접 고쳐야 합니다. `npx prisma db seed` 로는 **되지 않습니다**:

```ts
// prisma/seed.ts — 이미 있는 계정은 건드리지 않습니다
await db.user.upsert({ where: { username }, update: {}, create: { … } });
```

> 이 문서는 한동안 「시드하면 비밀번호가 새로 설정된다」고 적고 있었습니다.
> **거짓이었습니다.** `update: {}` 는 아무것도 안 바꿉니다 — 시드는 계정이
> **없을 때만** 만듭니다. 그대로 따랐다면 잠긴 채로 「했는데 안 된다」를
> 겪었을 것입니다.

관리자가 한 명도 없으면 아무것도 못 합니다 — 그래서 **마지막 관리자는 강등·정지·탈퇴가
서버에서 거부됩니다** (`FR-ADM-009`).

### 옛 아이디 `admin`

`master` 로 바꾸면서 **예약 목록에 넣었습니다** — 아무나 가입해서 감사 로그의
옛 이름과 헷갈리는 일을 막습니다. 자료 작성자와 감사 기록은 **이름만 바뀌고
그대로 이어집니다** (계정을 새로 만들지 않고 이름을 바꿨습니다).

## 7. AI 수집 계정 (`ai_collector`)

자료를 자동으로 모으는 전용 계정입니다. **사람이 로그인해 쓰는 계정이 아닙니다.**

| 항목 | 값 |
| --- | --- |
| 아이디 | `ai_collector` (표시 이름 「AI 수집기」) |
| 역할 | `EDITOR` — 자료 등록·수정만. 회원·분류 관리는 못 합니다 |
| 키 스코프 | `resources:read` · `resources:write` |
| 키 만료 | 발급일 + 1년 |

**`archive:run` 을 일부러 빼 두었습니다.** 아카이브는 저장소 소스를 통째로 내려받아
총량 상한(`DEC-022`)을 먹습니다 — 사람이 보고 판단할 일입니다. 관리자 화면에서
자료별로 실행하십시오.

### 키를 새로 발급하려면

`ai_collector` 로 로그인해 **마이페이지 > 보안 > API 키**에서 발급합니다.
평문은 **발급 직후 한 번만** 보입니다. 옛 키는 같은 화면에서 폐기하십시오.

> **키가 새면 계정을 정지하는 것으로 즉시 막힙니다.** 키 검증이 매 요청 소유자
> 상태를 보므로(`DEC-037`), 관리자 → 회원에서 정지하면 그 키는 그 순간부터
> 401 입니다. 정지를 풀면 그대로 살아납니다.

### 이 계정이 넣은 자료를 구분하려면

목록·상세에 **「CLI 수집」**으로 표시됩니다 (`source_channel = MCP`).
사람이 화면에서 넣은 것과 섞이지 않습니다.


**`loadtest` 는 운영 빌드에서 재십시오.**

```powershell
npm run build; npm start        # 다른 창에서 띄워 둔 채
```

`npm run dev` 로 재면 요청마다 컴파일 확인과 소스맵 생성이 끼어 **실제보다
나쁘게** 나옵니다. 더미 1만 건은 측정이 끝나면 스스로 지웁니다 (`--keep` 으로 남길 수 있습니다).

목표: 목록 P95 500ms · 검색 1초 · 상세 700ms (`NFR-PERF-001`·`002`·`004`).
셋 다 지키면 통과입니다. 2026-08-30 실측은 **354 · 381 · 422ms · 58.9 req/s** 였습니다.

> **보안·접근성 점검은 `npm run dev` 로도 됩니다.** 부하만 운영 빌드가 필요합니다.

## 9. 기록 정리 — 작업 · 감사 로그

두 화면에서 관리자가 직접 지울 수 있습니다.

| 어디 | 무엇을 | 남는 것 |
| --- | --- | --- |
| 관리자 → 작업 | 행 하나 삭제 · 「끝난 기록 정리」 일괄 | 일괄만 감사 로그에 |
| 관리자 → 감사 로그 | 「기록 정리」 — 시점 이전 일괄 | **지웠다는 사실이 새 줄로** |

**작업 모니터** — 완료·실패한 기록만 지웁니다. 대기·실행 중인 작업은 버튼이
아예 나오지 않습니다: 그건 「기록 삭제」가 아니라 「작업 취소」이고, 지우면
그 일은 영영 안 돌면서 아무도 모르게 됩니다.

**감사 로그** — 고를 수 있는 것은 **시점 하나**뿐입니다(1년 / 6개월 / 90일 /
30일 / 전부). 「이 사람 기록만」·「이 행위만」은 **일부러 만들지 않았습니다** —
그건 추적을 지우는 도구이고, 감사 로그가 있는 이유를 정면으로 거스릅니다.

> **지운 사실은 지워지지 않습니다.** 삭제와 기록이 한 트랜잭션이라, 정리한
> 직후 감사 로그 맨 위에 «누가 · 언제 · 몇 건 · 어느 시점 이전»이 새 줄로
> 남습니다. 「왜 작년 기록이 없느냐」의 답이 그 줄입니다.
>
> 보존 1년 자동 정리(`npm run maintenance`)도 **같은 함수**를 씁니다.

## 10. 도우미 채팅

서비스 화면 오른쪽의 도우미는 **이 PC 에 설치된 Claude Code CLI** 를 부릅니다.

| 항목 | 값 |
| --- | --- |
| 모델 자격 | CLI 의 로그인 (`claude auth status` → `subscriptionType`) |
| 앱이 가진 모델 키 | **없음** |
| 자료 검색 | `CHAT_API_KEY` (QueenBee 읽기 전용 키) |
| 동시 실행 | 2개까지, 한 번에 최대 120초 |

**청구는 따로 없습니다** — 구독 사용량을 씁니다. 다만 **팀 전체의 채팅이 이 PC
계정 하나의 한도**를 쓰므로, 많이 쓰면 운영자 본인의 Claude Code 작업이 먼저
느려집니다. 한도가 걸리면 채팅이 「대답을 받지 못했습니다」로 끝납니다.

**서버를 다른 Windows 사용자로 돌리면 채팅이 죽습니다.** CLI 의 로그인은 그
사용자 프로필(`C:\Users\…\.claude`)에 있습니다.

### 사내 전용입니다

**「찾아 줘」는 언제나 QueenBee 안을 찾습니다.** 도우미는 바깥을 뒤질 수 없고,
등록된 자료만 답합니다. 없으면 **「등록된 자료가 없습니다」**라고 말하고 다른
검색어를 제안합니다 — 빈손을 자기가 아는 바깥 이야기로 채우지 않습니다.

찾은 자료는 **자료 페이지 링크**로 옵니다. 눌러서 바로 갈 수 있어야 답입니다.

> 바깥 정보가 필요하면 도우미 말고 브라우저로 찾으십시오. 그리고 쓸 만하면
> **주소를 도우미에게 주면서 등록해 달라**고 하십시오 — 아래 자동 등록입니다.

### 자동 등록

「이 저장소 등록해 줘」처럼 말하면 **어느 화면에 있든** 도우미가 알아서 넣습니다.
넣기 전에 중복을 확인하고, 타입과 분류를 스스로 고릅니다.

**작성자는 요청한 사람입니다.** 도우미에게는 등록 도구가 없고, 무엇을 넣을지만
적어 내면 **서버가 로그인한 본인 이름으로** 만듭니다 — 도구를 줬다면
`CHAT_API_KEY` 의 주인(`ai_collector`)이 작성자가 됐을 것입니다.

검증은 **웹 폼·Ingest 와 같은 zod** 를 지납니다. 채팅만 다른 검증을 쓰면
화면으로는 못 넣는 값이 대화로는 들어갑니다.

> **잘못 들어갔으면 답 밑의 「되돌리기」**를 누르십시오. 휴지통으로 갑니다
> (30일 유예, `FR-RES-008`) — 영구 삭제가 아니라 관리자가 복구할 수 있습니다.

### 무엇을 못 하게 막았는가

도우미가 손에 쥐는 도구는 **QueenBee 읽기 다섯 개뿐**입니다. 웹 검색도,
이 PC 의 파일도, 자료를 고치는 도구도 없습니다.

- `--restricted` — Bash·코드 실행 도구가 **아예 없습니다**
- `--strict-mcp-config` — 이 PC 사용자의 개인 MCP 설정을 무시합니다
- `--disallowedTools` — 웹 검색·파일·다른 에이전트 도구를 **목록에서 지웁니다**
- `CHAT_API_KEY` 의 스코프가 **읽기뿐** — 쓰기 도구를 불러도 API 가 막습니다
- 등록도 도우미가 «직접» 하지 않습니다 — 위의 자동 등록을 보십시오

> **CLI 를 올린 뒤에는 `npm run verify:chat` 을 한 번 돌리십시오.** 새 버전이
> 도구를 늘리면 그 도구는 아무도 막은 적이 없습니다. 이 검사는 «막았다»를
> 믿지 않고 **CLI 에게 목록을 물어봅니다.**

### 안 될 때

| 화면에 뜨는 말 | 뜻 |
| --- | --- |

## 12. 팀에 열 때 (`DEC-023`)

> **`npm run dev` 로 열지 마십시오.** 개발 서버는 다른 주소에서 오는 요청의
> dev 전용 자산을 막습니다. 사내망 IP 로 들어가면 **화면은 뜨는데 자바스크립트가
> 하나도 안 실행되고, 버튼이 전부 먹통**이 됩니다 — 로그인도 안 됩니다.
> 아래 3번(`npm run build; npm start`)이 그래서 있습니다.
>
> 개발 중에 팀원이 잠깐 붙어 봐야 한다면 그대로 됩니다 — `next.config.ts` 가
> 이 PC 의 주소를 자동으로 허용합니다(`allowedDevOrigins`).

1. Windows 방화벽에서 **인바운드 3100 포트**를 허용합니다
2. `.env` 의 `APP_URL` 을 이 PC 의 IP 로 바꿉니다 (`http://192.168.x.x:3100`)
3. `npm run build; npm start` 로 다시 띄웁니다
4. 팀원에게 주소와 가입 방법을 알립니다 — 가입 후 **관리자 승인**이 필요합니다

> `APP_URL` 은 자료 링크와 MCP 설정 스니펫에 실립니다. `localhost` 로 두면
> 팀원이 받은 링크가 **자기 PC 를 가리킵니다.**

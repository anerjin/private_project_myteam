## 0. 새 세션 시작 절차

```mermaid
flowchart LR
    A["① 이 파일 읽기<br/>_docs/README.md"] --> B["② 최신 메모리 읽기<br/>99.memory/memory_NN.md 끝부분"]
    B --> C["③ 진행 상황 확인<br/>아래 4장"]
    C --> D["④ 필요한 폴더만 열기<br/>01 / 02 / 03"]
    D --> E["⑤ 작업"]
    E --> F["⑥ 메모리에 기록<br/>+ 관련 문서 갱신"]
```

1. **이 파일**을 읽는다 — 프로젝트가 무엇이고 문서가 어디 있는지 파악한다.
2. **`99.memory/` 에서 번호가 가장 큰 `memory_NN.md`** 를 열고 **끝부분**을 읽는다 — 직전에 무슨 작업을 했고 무엇이 남았는지 알 수 있다.
3. 아래 **4장 진행 상황**에서 현재 단계와 다음 할 일을 확인한다.
4. 작업에 필요한 폴더 문서만 연다. (전부 읽지 않는다)
5. 작업이 끝나면 **반드시** `99.memory` 에 기록하고, 바뀐 내용이 있으면 해당 문서를 갱신한다.

## 1. 프로젝트 한 줄 정의

**QueenBee** — DOI(드론 공간정보) 개발팀이 AI 자료 · GitHub 오픈소스 · MCP 서버 · Skill · 개발 참고 자료를
한곳에 모아 검색·재사용·보관하는 **사내 전용 정보 시스템**.

| 항목 | 값 |
| --- | --- |
| 서비스명 | **QueenBee** (소문자 식별자 `queenbee`) |
| 사용자 | DOI 개발팀 (동시 20명 내외, 총 계정 50개 이하) |
| 로그인 | **아이디 + 비밀번호** → **관리자 승인** 후 이용 (`DEC-014`) |
| 자료 접근 | 승인된 회원은 **모든 자료 열람** (`DEC-018`) |
| **자료 수집** | **Claude Code CLI + QueenBee MCP 서버** (주력) + 웹 등록 (`DEC-012`) |
| 구성 | 서비스 페이지 + 관리자 페이지 + Ingest API + MCP 서버 |
| 스택 | Next.js(App Router) · PostgreSQL · Redis · Prisma · shadcn/ui |
| **실행 (1단계)** | **현재 개발 PC(Windows 11)** — Docker Desktop + 호스트 실행 (`DEC-013`) |
| 실행 (2단계) | 사내 서버 + Docker Compose (`DEC-001`) |
| 파일 보관 | 이 PC 디스크 `E:\queenbee-data` — **로컬 파일시스템** (MinIO 미사용, `DEC-016`·`DEC-019`) |
| 외부 공개 | **하지 않음** (`DEC-017`) · 알림도 **인앱만** (`DEC-015`) |
| 개발 서버 | `http://localhost:3100` (포트 고정 — `DEC-028`) |
| 현재 단계 | **문서 완료 + `M0.5` UI 프로토타입 완료** (목 데이터로 전 화면 동작) |

핵심 설계 두 가지만 기억한다면:

1. **모든 콘텐츠는 `resources` 하나로 추상화**하고, 콘텐츠 타입은 폴더 하나 + 레지스트리 한 줄로 추가한다.
   → [REQ-04 콘텐츠 도메인 모델](01.요구사항/04_콘텐츠_도메인_모델.md)
2. **자료가 들어오는 입구는 둘(웹·CLI)이지만 로직은 하나**다. 둘 다 같은 service 계층을 지난다.
   → [DEV-08 자료 수집 파이프라인](02.개발설계/08_자료수집_파이프라인.md)

```
_docs/
├─ README.md                     ★ 이 파일 — 세션 진입점
├─ 01.요구사항/                   무엇을 만들 것인가          (그룹 코드 REQ)
├─ 02.개발설계/                   어떻게 만들 것인가          (그룹 코드 DEV)
├─ 03.의사결정_및_미해결사항/      왜 그렇게 정했나 / 못 정한 것 (그룹 코드 DCS)
├─ 99.memory/                    작업 기록                   (그룹 코드 MEM)
└─ _viewer/                      정적 문서 뷰어
```

| 폴더 | 담는 것 | 담지 않는 것 |
| --- | --- | --- |
| `01.요구사항` | 사용자가 무엇을 할 수 있어야 하는가, 지켜야 할 제약 | 테이블·API·폴더 구조 |
| `02.개발설계` | 아키텍처, 데이터 모델, 화면, API, 폴더 규약, 일정 | "무엇이 필요한가" |

| `99.memory` | 언제 무엇을 했는지 시간순 기록 | 정리된 결론 (그건 01~03) |

> **하위 폴더를 만들지 않습니다.** 뷰어는 `_docs/<폴더>/*.md` 한 겹만 스캔합니다.

## 6. 문서 작성 규칙

1. **한 문서 = 한 관심사.** 새 주제는 문서를 추가하지, 기존 문서를 부풀리지 않는다.
2. 모든 문서 상단에 **메타 표**(문서 ID / 버전 / 상태 / 최종 수정일)를 둔다.
3. 상태는 `Draft` → `Review` → `Confirmed` 순으로 올린다. `Confirmed` 이후 변경은 하단 **변경 이력**에 남긴다.
4. 결정을 바꿀 때는 해당 문서만 고치지 말고 **`DCS-01`** 을 함께 갱신한다.
5. 못 정한 것은 `TBD` 로 두지 말고 **`DCS-02` 에 `OPEN-xxx`** 로 등록한 뒤 본문에서 그 ID를 참조한다.
6. 다이어그램은 **Mermaid** 로 작성한다. (뷰어가 렌더링한다)
7. 파일명은 `NN_주제.md`. 앞 두 자리 숫자가 문서 ID가 된다.
8. **하위 폴더를 만들지 않는다.**
9. 다른 폴더 문서를 링크할 때는 상대 경로를 쓴다. 예: `../02.개발설계/02_데이터_모델.md`

## 7. 메모리(작업 기록) 규칙

`_docs/99.memory/` 는 **무엇을 했는지 시간순으로** 남기는 곳입니다. 정리된 결론은 `01~03` 에 두고, 여기에는 **과정과 맥락**을 남깁니다.

| 규칙 | 내용 |
| --- | --- |
| 파일명 | `memory_01.md`, `memory_02.md` … 순번 |
| 분할 기준 | **1,200 라인을 넘으면 다음 번호 파일을 새로 만든다.** 기존 파일은 수정하지 않는다 |
| 기록 순서 | 시간순. **새 항목을 파일 끝에 추가**한다 (위에 끼워 넣지 않는다) |
| 기록 시점 | 작업 단위가 끝날 때마다. 세션이 끝나기 전에 반드시 |
| 읽는 법 | 새 세션은 **번호가 가장 큰 파일의 끝부분**만 읽으면 된다 |
| 새 파일 시작 시 | 파일 맨 위에 직전 파일의 마지막 상황을 3~5줄로 요약해 이어 붙인다 |

### 기록 항목 형식

```markdown
## [NNN] 2026-08-28 · 작업 제목

- **한 일:** 무엇을 했는지 (파일·문서 ID 명시)
- **이유:** 왜 했는지
- **결정:** 이 작업에서 확정한 것 (있으면 DEC-0NN 도 함께 등록)
- **남은 것:** 다음 세션이 이어서 할 일
```

## 8. 문서 뷰어

`_docs/_viewer` 에 정적 뷰어가 있습니다. 마크다운을 고친 뒤 다시 빌드하면 됩니다.

```powershell
# 1회 갱신
node _docs/_viewer/build.mjs

# 편집 중 자동 갱신 (Ctrl+C 종료)
node _docs/_viewer/build.mjs --watch
```

빌드 후 `_docs/_viewer/index.html` 을 브라우저로 엽니다. (`file://` 로도 동작)

새 폴더를 추가할 때는 `build.mjs` 의 `KNOWN` 에 **고정 코드**를 등록하세요.
등록하지 않으면 자동 코드(`G1`/`G2`…)를 받고, 폴더가 늘 때마다 문서 ID가 조용히 밀립니다.

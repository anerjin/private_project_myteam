## 3.2 AUTH — 인증

| ID | 기능 | 설명 | 우선순위 |
| --- | --- | --- | :---: |
| FR-AUTH-001 | 회원가입 | **아이디**·비밀번호·이름·소속·가입 사유를 입력해 신청한다 | P0 |
| FR-AUTH-002 | 아이디 중복 검사 | 가입 중 실시간으로 사용 가능 여부를 표시한다. **점유된 아이디도 사용 불가**(`DEC-021`) | P0 |
| FR-AUTH-004 | 비밀번호 규칙 검증 | 클라이언트·서버 양쪽에서 동일 규칙으로 검증한다 | P0 |
| FR-AUTH-006 | 로그인 | **아이디**·비밀번호로 로그인한다 | P0 |
| FR-AUTH-007 | 계정 상태별 분기 | 상태에 따라 진입/차단/안내 화면을 다르게 보여준다 | P0 |
| FR-AUTH-008 | 로그인 상태 유지 | 체크 시 7일 유지, 미체크 시 브라우저 종료까지 | P0 |
| FR-AUTH-009 | 로그아웃 | 세션을 삭제하고 로그인 화면으로 이동한다 | P0 |
| FR-AUTH-011 | 초기 비밀번호 변경 강제 | 관리자가 초기화한 비밀번호로 로그인하면 변경 화면으로 강제 이동 | P0 |
| FR-AUTH-012 | 로그인 시도 제한 | 계정·IP 단위로 실패 횟수를 제한한다 | P1 |

### 상세 수용 기준

**FR-AUTH-001 회원가입**
- 필수: 아이디, 비밀번호, 비밀번호 확인, 이름, 소속(팀), 개인정보 수집 동의
- 선택: 가입 사유(관리자 승인 판단용, 200자)
- 아이디 규칙: 영문 소문자·숫자·`_`·`.` 4~20자, 첫 글자는 영문. 대소문자 구분 없이 유일
- 성공 시 `status=PENDING`, `role=MEMBER`로 생성되고 `/pending` 으로 이동한다
- 실패 시 입력값은 유지되고 필드별 오류 메시지가 표시된다
- **탈퇴한 계정의 아이디는 재사용할 수 없다** (과거 기록의 주체가 섞이면 안 된다)

**FR-AUTH-006 로그인**
- 실패 메시지는 아이디/비밀번호를 구분하지 않는다
- `next` 파라미터가 있으면 로그인 후 해당 경로로 이동한다 (사이트 내부 경로만 허용 — 오픈 리다이렉트 방지)
- 성공 시 세션 생성 및 `last_login_at` 갱신

**FR-AUTH-007 계정 상태별 분기**

| 상태 | 결과 |
| --- | --- |
| `PENDING` | `/pending` — "승인 대기 중입니다" + 신청일시 표시 |
| `ACTIVE` | `/dashboard` |
| `REJECTED` | 로그인 화면 — "가입이 거부되었습니다" + 거부 사유 |
| `SUSPENDED` | 로그인 화면 — "이용이 정지된 계정입니다" + 문의 안내 |
| `WITHDRAWN` | 로그인 화면 — "존재하지 않는 계정입니다" |

| FR-USER-002 | 프로필 수정 | 이름·소속·프로필 이미지·자기소개를 수정한다 (아이디는 변경 불가) | P0 |

**FR-USER-007 탈퇴 처리 규칙**
- 등록한 자료는 유지하되 작성자 표기를 "탈퇴한 사용자"로 바꾼다
- 개인 컬렉션·북마크는 삭제한다
- 발급한 API 키를 모두 폐기하고 전 세션을 만료시킨다
- 계정 레코드는 이름 마스킹 후 보존하고, **1년 뒤 배치가 익명화**한다 (`DEC-021`)
- **아이디는 `reserved_usernames` 에 점유되어 재사용되지 않는다**
- `ADMIN` 이 1명뿐이면 탈퇴를 거부한다

**FR-USER-008 API 키 관리 수용 기준**
- 마이페이지 **보안** 탭에서 발급한다. 용도 이름과 스코프를 지정한다
- 발급 직후 **한 번만** 전체 키를 보여준다. 이후에는 `qb_live_a1b2…` 형태의 prefix만 표시
- 목록에 이름·스코프·생성일·마지막 사용일·만료일을 보여준다
- 폐기는 확인 다이얼로그를 거치고 **즉시** 적용된다
- 사용자당 최대 5개. 초과 시 발급 버튼이 비활성화되고 사유를 안내한다
- 상세 정책은 [REQ-02 · 2.8절](02_사용자_권한_정책.md)

### 상세 수용 기준

**FR-RES-005 URL 빠른 등록**
- 대시보드 상단 입력창에 URL을 붙여넣고 Enter → 등록 폼이 자동으로 채워진다
- URL 패턴으로 타입을 추정한다
  - `github.com/{owner}/{repo}` → `GITHUB_REPO`
  - `arxiv.org/…`, `*.pdf` → `AI_MATERIAL`(논문)
  - `youtube.com`, `youtu.be` → `AI_MATERIAL`(영상)
  - 그 외 → `AI_MATERIAL`(아티클)
- 메타 수집 실패해도 등록은 계속 진행되며, 제목은 사용자가 직접 입력한다
- 수집은 3초 안에 응답하지 못하면 백그라운드 Job으로 넘기고 폼을 먼저 연다

**FR-RES-007 자료 삭제**
- `deleted_at` 을 채우는 소프트 삭제. 목록·검색에서 제외된다
- 삭제자·삭제 시각을 기록한다
- 관리자 페이지 휴지통에서 30일간 복구 가능하며, 이후 정리 배치 대상이 된다

**FR-RES-011 중복 감지**
- 정규화한 URL(스킴·`www.`·트래킹 파라미터·끝 슬래시 제거) 기준으로 비교한다
- 중복이면 "이미 등록된 자료입니다" + 기존 자료 카드를 보여주고, 이동/그래도 등록 중 선택하게 한다

## 3.6 GH — GitHub 연동

| ID | 기능 | 설명 | 우선순위 |
| --- | --- | --- | :---: |
| FR-GH-001 | 저장소 메타 수집 | URL로 스타·포크·언어·라이선스·토픽·설명·최근 커밋일을 가져온다 | P0 |
| FR-GH-002 | README 저장 | 기본 브랜치의 README를 내려받아 저장·렌더링한다 | P0 |
| FR-GH-003 | 소스 아카이브 | tarball/zip을 내려받아 사내 스토리지에 보관한다 | P0 |
| FR-GH-004 | 아카이브 다운로드 | 보관된 아카이브를 다시 내려받는다 | P0 |
| FR-GH-005 | 메타 갱신 | 수동 또는 주기적으로 최신 메타를 다시 가져온다 | P1 |
| FR-GH-006 | 릴리스 정보 | 최신 릴리스 태그·게시일을 함께 보관한다 | P1 |
| FR-GH-007 | 원본 소실 감지 | 저장소가 삭제·비공개로 바뀌면 표시하고 아카이브를 강조한다 | P1 |
| FR-GH-008 | 토큰 관리 | GitHub 토큰을 설정하고 잔여 rate limit을 확인한다 | P2 |

### 상세 수용 기준

**FR-GH-003 소스 아카이브**
- 실행 시 즉시 `Job`을 만들고, 화면에는 "아카이브 준비 중" 상태를 표시한다
- 기본 브랜치의 특정 커밋 SHA를 기준으로 받고, 그 SHA를 함께 기록한다
- 저장 경로 규칙: `archives/{owner}/{repo}/{sha}.tar.gz`
- **자동 아카이브를 하지 않는다.** 사용자가 명시적으로 실행할 때만 수행한다 (`DEC-022`)
- **단일 아카이브 최대 크기 500MB.** 초과하면 실패로 기록하고 사유를 남긴다
- **총량 상한 100GB.** 80GB에서 경고하고, 100GB에 닿으면 신규 아카이브를 거부한다 (`DEC-022`)
- 디스크 여유가 임계치 미만이면 실행을 거부한다 (`NFR-BACKUP-007`)
- 동일 SHA가 이미 있으면 재다운로드하지 않고 기존 것을 재사용한다
- 실패 시 최대 3회 지수 백오프 재시도, 이후 `FAILED` 로 종료

**FR-GH-001 rate limit 처리**
- 남은 호출이 임계치 이하이면 새 수집 요청을 큐에 쌓고 리셋 시각 이후 처리한다
- 관리자 화면에 남은 호출 수와 리셋 시각을 표시한다

### 상세 수용 기준

**FR-CLI-002 타입 스키마 조회**
- 서버가 zod 스키마에서 생성한 JSON Schema를 그대로 내려준다
- **콘텐츠 타입이 늘어도 MCP 서버 코드를 고치지 않아도 된다** ([REQ-04 · 4.9절](04_콘텐츠_도메인_모델.md))
- 비활성(`is_active = false`) 타입은 목록에서 제외한다

**FR-CLI-004 중복 확인**
- 웹과 **동일한 URL 정규화 규칙**을 쓴다 (`FR-RES-011`)
- 중복이면 오류가 아니라 기존 자료 정보를 반환한다. 등록할지 말지는 에이전트·사람이 판단한다

**FR-CLI-005 자료 등록**
- 웹 등록과 **같은 서비스 계층**을 거친다. 검증·중복·감사 규칙이 갈라지면 안 된다
- `source_channel = MCP` 로 생성된다. **검수 대기 같은 별도 상태는 붙이지 않는다** (`DEC-029`)
- 확인하지 못한 값(스타 수·라이선스 등)은 비워 보내고 **서버 워커가 채운다**
- 검증 실패 시 어떤 필드가 왜 틀렸는지 그대로 돌려준다. 에이전트가 고쳐 재시도할 수 있어야 한다
- **자동 재시도를 하지 않는다.** 등록은 부작용이 있어 조용한 재시도가 중복을 만든다

**FR-CLI-009 수집 Skill**
- 수집 절차(검색 → 선별 → 중복 확인 → 요약 → 분류 → 등록)와 품질 규칙을 정의한다
- `applicability`(사내 적용 아이디어)를 비워 두지 않도록 강제한다
- 한 대화에서 10건을 넘겨 등록하지 않도록 안내한다 (한 번에 쏟아부으면 품질이 떨어진다)
- 이 Skill 자체를 QueenBee에 `CT-SKILL` 자료로 등록한다

**공통 — 인증**
- 개인 API 키로 인증한다 (`FR-USER-008`, [REQ-02 · 2.8절](02_사용자_권한_정책.md))
- 키의 권한은 **발급자의 역할을 넘지 못한다**
- 소유자 계정이 `ACTIVE` 가 아니면 즉시 무효
- 모든 쓰기 작업은 `via=MCP` 로 감사 로그에 남는다

**FR-ADM-004 승인/거부 수용 기준**
- 승인 시 부여할 역할을 선택할 수 있다 (기본 `MEMBER`)
- 일괄 승인은 최대 50건까지 한 번에 처리하고, 결과를 성공/실패로 나눠 보여준다
- 거부 사유는 10자 이상 필수이며 신청자에게 그대로 전달된다
- 모든 처리는 감사 로그에 남는다

**FR-ADM-012 카테고리 관리 수용 기준**
- 트리는 **2단계까지**다 (`FR-SRCH-006`). 하위의 하위는 만들 수 없고, DB 트리거
  `trg_categories_depth` 가 이를 강제한다 — 화면이 막는 것이 아니라 스키마가 막는다
- 하위가 딸린 대분류를 지울 때 **자료를 어디로 옮길지** 고르게 한다 (자료 이관)
- 생성·수정·순서 변경·삭제는 모두 감사 로그에 남는다

> **`FR-SRCH-006` 과 나누는 선**: 「2단계」라는 **구조**는 `FR-SRCH-006`,
> 그 구조를 **편집**하는 것은 여기입니다. 전에는 `FR-SRCH-006` 이
> 「2단계 트리로 카테고리를 **관리**한다」여서 두 번호가 같은 일을 가리켰고,
> `P4` 를 닫을 때 「`P0` 인데 안 만들었다」로 걸렸습니다 (`DEC-049`).

**FR-ADM-014 콘텐츠 타입 설정 수용 기준**
- 타입 정의(스키마) 자체는 코드에 있고, 이 화면에서는 **운영 설정만** 바꾼다
- 설정 항목: 활성 여부, 표시 라벨, 아이콘, 사이드바 노출 여부, 정렬 순서, 설명
- 비활성화해도 기존 자료는 지워지지 않으며 목록·검색에서만 숨겨진다

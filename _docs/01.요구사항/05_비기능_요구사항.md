### 성능 확보 수단

| 수단 | 적용 지점 |
| --- | --- |
| 목록은 **커서 페이지네이션** | `id`/`created_at` 복합 커서. OFFSET 사용 금지 |
| N+1 차단 | Prisma `include` 로 한 번에 조회, 목록에서 상세 테이블 조인 최소화 |
| 카운트 비정규화 | `view_count`, `bookmark_count` 를 컬럼으로 유지 |
| Redis 캐시 | 카테고리 트리, 태그 목록, 대시보드 통계, 콘텐츠 타입 설정 |
| Next.js 캐시 | 정적 요소는 `revalidate`, 사용자별 데이터는 캐시하지 않음 |
| 이미지 최적화 | `next/image` + WebP 변환 |
| 인덱스 | [DEV-02 데이터 모델](../02.개발설계/02_데이터_모델.md) 인덱스 절 참조 |

## 5.2 SEC — 보안

| ID | 항목 | 요구사항 |
| --- | --- | --- |
| NFR-SEC-001 | 인증 | 비밀번호는 Argon2id 해시로만 저장. 평문·복호화 가능 형태 금지 |
| NFR-SEC-002 | 무차별 대입 방어 | 계정 5회/10분, IP 20회/10분 실패 시 잠금 ([REQ-02 · 2.6절](02_사용자_권한_정책.md)) |
| NFR-SEC-003 | 인가 | 모든 Server Action·Route Handler 진입부에서 역할·소유권 검사 |
| NFR-SEC-004 | 전송 구간 | **2단계(사내 서버) HTTPS 필수.** 1단계 개발 PC는 `http://localhost` 로 운영하며, 외부에 공개하지 않는 것을 전제로 한다 (`DEC-013`·`DEC-017`) |
| NFR-SEC-005 | 세션 | `HttpOnly` + `SameSite=Lax` 쿠키. `Secure` 는 HTTPS 환경에서만 켠다. 상태 변경 시 세션 무효화 |
| NFR-SEC-006 | 입력 검증 | 모든 외부 입력은 서버에서 zod로 재검증. 클라이언트 검증만 신뢰 금지 |
| NFR-SEC-007 | XSS | 마크다운 렌더링 시 HTML sanitize (`rehype-sanitize`). `dangerouslySetInnerHTML` 직접 사용 금지 |
| NFR-SEC-008 | 비밀값 유입 차단 | 자료 본문·설정 JSON에 토큰 패턴(`ghp_`, `sk-`, AWS 키 등)이 감지되면 저장을 거부하고 경고 |
| NFR-SEC-009 | 파일 업로드 | 확장자 + MIME + **매직 넘버** 3중 검증. 실행 파일 차단. 선언 크기와 실제 기록 바이트를 모두 확인 |
| NFR-SEC-010 | SSRF | 사용자 입력 URL 수집 시 사설 IP 대역(10./172.16./192.168./127./169.254.) 차단 |
| NFR-SEC-011 | 오픈 리다이렉트 | `next` 파라미터는 사이트 내부 경로만 허용 |
| NFR-SEC-012 | 비밀 관리 | 자격 증명은 환경 변수로만. 저장소에 커밋 금지. `.env.example` 만 커밋 |
| NFR-SEC-013 | 의존성 | 월 1회 `npm audit` 확인, 심각도 High 이상은 즉시 대응 |
| NFR-SEC-014 | 보안 헤더 | CSP, `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options: DENY` |
| NFR-SEC-015 | 감사 추적 | 권한·계정·자료 관련 행위는 모두 감사 로그 기록 |
| NFR-SEC-016 | 에러 노출 | 사용자에게 스택 트레이스·SQL·내부 경로 노출 금지 |
| NFR-SEC-017 | **API 키** | 원문 저장 금지(SHA-256 해시 + prefix). 발급자의 역할을 넘는 권한 부여 금지. 소유자가 `ACTIVE` 가 아니면 즉시 무효. 키 단위 레이트리밋 적용 ([REQ-02 · 2.8절](02_사용자_권한_정책.md)) |
| NFR-SEC-018 | **Ingest API 격리** | CLI 경로도 웹과 **같은 인가·검증 계층**을 통과한다. 별도 우회 경로를 만들지 않는다 |
| NFR-SEC-019 | **파일 경로 이탈 방어** | 저장 키는 **서버만 생성**하고 사용자 파일명을 경로에 쓰지 않는다. 접근 전 `STORAGE_ROOT` 하위인지 매번 검증한다 (`DEC-019`) |
| NFR-SEC-020 | **파일 응답 헤더** | `Content-Disposition: attachment` + `X-Content-Type-Options: nosniff`. 업로드된 파일이 브라우저에서 실행되지 않게 한다 |
| NFR-SEC-021 | **파일 접근 통제** | 파일은 로그인·권한 검사를 거친 요청으로만 내려준다. 웹에서 직접 열리는 경로(`public/`)에 두지 않는다 |

### CSRF

Server Action은 Next.js가 오리진을 검증하므로 기본 보호가 있습니다.
직접 만든 Route Handler 중 상태를 바꾸는 것은 **`Origin` 헤더 검증**을 추가합니다.

### 필수 E2E 시나리오

1. 회원가입 → 승인 대기 → 관리자 승인 → 로그인 → 대시보드 진입
2. GitHub URL 등록 → 메타 수집 → 상세 확인 → 아카이브 실행
3. 자료 검색 → 필터 → 상세 → 북마크
4. 권한 없는 사용자가 `/admin` 접근 시 차단
5. 관리자 정지 처리 → 해당 사용자 즉시 로그아웃 확인

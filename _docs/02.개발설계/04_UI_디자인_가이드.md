## 4.1 shadcn/ui 를 쓰는 방식

shadcn/ui는 npm 패키지가 아니라 **소스 코드를 내 프로젝트로 복사해 오는 방식**입니다.
따라서 다음 원칙을 지킵니다.

| 원칙 | 이유 |
| --- | --- |
| `components/ui/*` 는 **가급적 수정하지 않는다** | 나중에 `shadcn add`로 갱신할 때 충돌한다 |
| 우리 규칙이 필요하면 **감싸서** 만든다 | `components/common/PageHeader.tsx` 처럼 조합 컴포넌트로 |
| 부득이하게 `ui/` 를 고치면 파일 상단에 주석으로 이유를 남긴다 | 갱신 시 판단 근거가 된다 |
| 컴포넌트는 **필요할 때 하나씩** 추가한다 | 안 쓰는 코드가 쌓이지 않게 |

---

## 4.2 설치 절차

프로젝트 생성 직후 한 번만 수행합니다.

```powershell
# 1) Next.js 프로젝트 생성 (TypeScript · Tailwind · App Router · src 디렉터리 사용)
npx create-next-app@latest project

# 2) shadcn 초기화 — 스타일·베이스 컬러·CSS 변수 사용 여부를 묻는다
npx shadcn@latest init

# 3) 로그인 화면 블록
npx shadcn@latest add login-03

# 4) 대시보드 레이아웃 블록
npx shadcn@latest add dashboard-01

# 5) 이후 필요한 개별 컴포넌트
npx shadcn@latest add button card input label form select textarea checkbox switch `
  badge avatar dropdown-menu dialog alert-dialog sheet tabs table `
  skeleton sonner tooltip popover command separator scroll-area `
  breadcrumb pagination alert progress calendar
```

### `init` 선택값

| 질문 | 선택 |
| --- | --- |
| Style | `new-york` |
| Base color | `slate` |
| CSS variables | `yes` (테마 토큰을 CSS 변수로 관리) |

## 4.3 블록 도입 후 정리

`add login-03` 과 `add dashboard-01` 은 **여러 파일을 한꺼번에 생성**합니다.
생성 목록은 설치 직후 `git status` 로 확인하고, 아래 기준으로 재배치합니다.

### login-03

| 생성물 | 우리 프로젝트에서의 처리 |
| --- | --- |
| 로그인 페이지 | `src/app/(public)/login/page.tsx` 로 이동 |
| 로그인 폼 컴포넌트 | `src/features/auth/components/login-form.tsx` 로 이동 |
| 기본 shadcn 컴포넌트 | `src/components/ui/` 유지 |

**필수 수정 사항**

1. 소셜 로그인 버튼과 구분선을 **삭제**한다 (자체 인증만 사용 — `DEC-002`)
2. **이메일 입력을 아이디 입력으로 바꾼다** — `type="text"`, `autocomplete="username"`, 라벨 "아이디" (`DEC-014`)
3. **"비밀번호를 잊으셨나요?" 링크를 삭제**하고, 대신 카드 하단에 안내 문구를 둔다 —
   *"비밀번호를 잊으셨다면 관리자에게 초기화를 요청하세요."* (메일 발송이 없다 — `DEC-015`)
4. 폼을 `react-hook-form` + `zod` 로 교체하고 Server Action에 연결한다
5. "로그인 상태 유지" 체크박스를 추가한다 (`FR-AUTH-008`)
6. 문구를 한국어로 바꾸고 로고 자리에 QueenBee 로고를 넣는다
7. 오류 표시용 `Alert` 영역을 폼 상단에 추가한다 ([DEV-03 · SCR-001](03_화면_정의_IA.md))
8. 회원가입 화면(`SCR-002`)은 이 레이아웃을 복제해 필드만 확장한다

### dashboard-01

| 생성물 | 우리 프로젝트에서의 처리 |
| --- | --- |
| 대시보드 페이지 | `src/app/(service)/dashboard/page.tsx` 로 이동 |
| 사이드바 · 헤더 · 네비게이션 컴포넌트 | `src/components/layout/` 로 이동 |
| 통계 카드 · 차트 · 데이터 테이블 | `src/features/dashboard/components/` 로 이동 |
| `sidebar` 등 기반 컴포넌트 | `src/components/ui/` 유지 |

**필수 수정 사항**

1. 사이드바 메뉴를 **데이터로 분리**한다 → `src/config/navigation.ts`
   - 자료 메뉴는 `content_type_settings` 를 읽어 **동적으로 생성**한다. 하드코딩하지 않는다
2. 서비스용 레이아웃과 관리자용 레이아웃 **두 개**로 복제하고 메뉴만 교체한다
   - `src/app/(service)/layout.tsx`, `src/app/(admin)/layout.tsx`
3. 헤더에 커맨드 팔레트(`Ctrl+K`), 알림 벨, 테마 토글을 추가한다
4. 샘플 데이터·더미 차트 데이터를 모두 제거한다
5. 사이드바 접힘 상태를 쿠키에 저장한다
6. 사용자 카드에 실제 세션 정보를 연결한다

> **중요:** 블록 코드에 남아 있는 샘플 데이터(`data.json` 등)를 그대로 두면 운영에 섞여 들어갑니다.
> 도입 직후 첫 커밋에서 반드시 제거합니다.

## 4.4 디자인 토큰

`globals.css` 의 CSS 변수를 단일 출처로 씁니다. 컴포넌트에서 색상 값을 직접 쓰지 않습니다.

| 토큰 | 용도 |
| --- | --- |
| `--background` / `--foreground` | 기본 배경·전경 |
| `--card` / `--card-foreground` | 카드 |
| `--primary` / `--primary-foreground` | 주요 액션 |
| `--secondary` | 보조 액션 |
| `--muted` / `--muted-foreground` | 비활성·보조 텍스트 |
| `--accent` | 강조·호버 |
| `--destructive` | 삭제·오류 |
| `--border` / `--input` / `--ring` | 테두리·입력·포커스 링 |
| `--radius` | 모서리 반경 |

### 확장 토큰 (프로젝트 고유)

콘텐츠 타입 배지 색은 타입별로 고정합니다. 타입 정의(`meta.ts`)에 함께 둡니다.

| 타입 | 배지 색 계열 |
| --- | --- |
| AI 자료 | violet |
| GitHub 저장소 | slate |
| MCP 서버 | emerald |
| Skill | amber |
| 개발 노트 | sky |

상태 색:

| 상태 | 색 |
| --- | --- |
| 승인 대기 / 검토 중 | amber |
| 활성 / 사용 중 | emerald |
| 정지 / 실패 | red |
| 보관 / 사용 중단 | slate |

> **주의:** 상태를 색으로만 구분하지 않습니다. 반드시 텍스트 라벨을 함께 씁니다. (`NFR-A11Y-004`)

### 타이포그래피

| 용도 | 크기 | 굵기 |
| --- | --- | --- |
| **페이지 제목** (헤더 빵부스러기 마지막 조각 = `h1`) | `text-sm` | `font-medium` |
| 본문 상단 강조 문구 (대시보드 인사말 등, heading 아님) | `text-2xl` | `font-semibold` |
| 섹션 제목 | `text-lg` | `font-semibold` |
| 카드 제목 | `text-base` | `font-medium` |
| 본문 | `text-sm` | `font-normal` |
| 보조 텍스트 | `text-xs` | `text-muted-foreground` |
| 코드 | `font-mono text-sm` | |

- 한글 폰트: `Pretendard` (사내망 정적 서빙) → 없으면 시스템 폰트 스택
- 코드 폰트: `JetBrains Mono` 또는 시스템 monospace

**제목 규칙 (`DEV-03 · 3.4절`)**

| 규칙 | 이유 |
| --- | --- |
| 페이지 제목은 **헤더 한 줄**에만 둔다 | 본문에 다시 두면 같은 글자가 두 번 나온다 |
| 그 조각이 **문서의 유일한 `h1`** 이다 | `h1` 이 둘이면 스크린리더가 문서의 제목을 특정하지 못한다 |
| 본문의 큰 글씨는 heading 이 아니다 | 대시보드 인사말처럼 **제목이 아닌** 문구는 `p` 로 둔다 |
| 크기가 작아진 만큼 위치로 읽힌다 | 헤더 맨 왼쪽 · `font-medium` · `text-foreground` 로 조상 조각과 구분한다 |

## 4.5 컴포넌트 규약

### 폼

```
react-hook-form (상태) + zod (검증) + shadcn Form (표현) + Server Action (제출)
```

| 규칙 | 내용 |
| --- | --- |
| 검증 스키마 | `features/<domain>/schema.ts` 에 두고 **클라이언트·서버가 같은 스키마를 공유**한다 |
| 오류 표시 | 필드 하단 텍스트. 제출 실패 시 첫 오류 필드로 포커스 이동 |
| 제출 중 | 버튼 `disabled` + 스피너 + 텍스트 유지("저장 중…") |
| 필수 표시 | 라벨 옆 `*` + `aria-required` |
| 비활성 필드 | 이유를 툴팁으로 안내 |
| 이탈 방지 | 변경사항이 있으면 `beforeunload` + 라우트 이탈 확인 |

### 테이블

| 규칙 | 내용 |
| --- | --- |
| 라이브러리 | TanStack Table + shadcn `table` |
| 정렬 | 헤더 클릭. 현재 정렬 상태를 아이콘으로 표시 |
| 선택 | 체크박스 + "N개 선택됨" 표시 + 일괄 액션 바 |
| 행 액션 | 우측 끝 `⋯` 드롭다운 |
| 빈 상태 | 테이블 내부에 안내 행 |
| 모바일 | 테이블 대신 카드 목록으로 전환 |
| 로딩 | 행 개수만큼 Skeleton 행 |

### 다이얼로그

| 종류 | 사용처 |
| --- | --- |
| `Dialog` | 입력이 필요한 작업 (거부 사유 입력, 컬렉션에 담기) |
| `AlertDialog` | 되돌릴 수 없는 작업 (영구 삭제, 강제 탈퇴) |
| `Sheet` | 모바일 사이드바, 상세 필터 패널 |
| `Popover` | 가벼운 선택 (태그 선택, 날짜 선택) |
| `Command` | 전역 검색 (`Ctrl+K`) |

### 삭제 확인 규약

되돌릴 수 있는지에 따라 확인 강도를 다르게 합니다.

| 대상 | 되돌리기 | 확인 방식 | 사후 |
| --- | --- | --- | --- |
| 자료 삭제 (`FR-RES-007`) | 휴지통 30일 | `AlertDialog` 확인 한 번 | 토스트에 **`실행 취소`** 액션 5초 |
| 자료 영구 삭제 (`FR-RES-009`) | **불가** | `AlertDialog` + **제목 직접 입력** | 되돌릴 수 없음을 문구로 명시 |
| 회원 거부 (`FR-ADM-004`) | 관리자가 되돌림 | `Dialog` + **사유 10자 이상** | 사유가 신청자에게 전달됨 |
| 회원 정지 (`FR-ADM-005`) | 해제 가능 | `Dialog` + 사유 | 세션·API 키 즉시 무효 |
| API 키 폐기 (`FR-USER-008`) | **불가** | `AlertDialog` 확인 한 번 | 즉시 적용 |

> **실행 취소를 제공하는 곳에서는 확인을 가볍게, 되돌릴 수 없는 곳에서는 무겁게** 합니다.
> 모든 삭제에 제목 입력을 요구하면 사람들이 읽지 않고 그대로 복사해 붙여넣게 됩니다.

### 알림

| 종류 | 사용처 |
| --- | --- |
| `Sonner` 토스트 | 작업 결과 (성공·실패) |
| `Alert` | 화면 안에 계속 보여야 하는 상태 (로그인 오류, 승인 대기 안내) |
| 배너 | 시스템 공지, 관리자 경고 |
| 인앱 알림함 | 비동기 결과, 승인 알림 |

### 아이콘

> **이모지를 아이콘으로 쓰지 않습니다.** 예외 없습니다.

| 규칙 | 내용 |
| --- | --- |
| 아이콘 출처 | **`lucide-react` 만** 사용합니다. 다른 아이콘 세트를 섞지 않습니다 |
| **이모지 금지** | 버튼·배지·로고·빈 상태·파비콘 어디에도 이모지를 쓰지 않습니다 |
| 금지하는 이유 | OS·브라우저마다 모양과 크기가 달라 통제할 수 없다 · 색을 테마 토큰에 맞출 수 없다 · 스크린리더가 이름을 제멋대로 읽는다 · 굵기가 주변 lucide 아이콘과 어긋나 조잡해 보인다 |
| 브랜드 마크 | `components/layout/brand-mark.tsx` 한 곳에서만 정의합니다. 사이드바·로그인 화면이 이것을 씁니다 |
| 파비콘 | `app/icon.svg` — lucide `hexagon` 을 SVG로 옮겼습니다. 이모지 data URI를 쓰지 않습니다 |
| 기본 크기 | `size-4`, 페이지 헤더는 `size-5` |
| 접근성 | 아이콘 전용 버튼에는 `aria-label` 필수 (`NFR-A11Y-005`) |

**본문 속 화살표(`→`)나 문서의 기호는 아이콘이 아닙니다.** 문장 부호로 쓰는 것은 무방합니다.

## 4.7 다크 모드

- `next-themes` 사용, `class` 전략
- 라이트 / 다크 / **시스템** 3가지. 기본값은 시스템
- 헤더 토글로 전환, 선택은 `localStorage` 저장
- SSR 깜빡임 방지를 위해 `<html>` 에 `suppressHydrationWarning` 적용
- **다크 모드에서도 대비 4.5:1 이상**을 유지합니다. 두 모드 모두에서 확인하고 머지합니다

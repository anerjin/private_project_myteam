### 밝기: 토큰만 되돌리면 «절반»입니다

패널은 상자에 `.dark` 를 박아 두어 언제나 어두웠습니다. 고르게 하려면 어두운
조상 **«안»에서** 밝은 값으로 되돌릴 자리가 있어야 합니다. `:root` 의 선택자를
`:root, .light` 로 늘려 그 자리를 만들었습니다(베끼지 않았습니다).

**그것만으로는 안 됩니다.** `dark:` 유틸리티가 그대로 살아납니다 — 변형이
`&:is(.dark *)` 였고 `html.dark > aside.light` 의 요소는 여전히 `.dark` 의
후손입니다. 말풍선의 `dark:prose-invert` 가 **흰 바탕에 흰 글씨**를 만듭니다.

```css
@custom-variant dark (&:is(:is(.dark *):not(.light *), .light .dark *));
```

| 바깥 | 안 | 되어야 하는 것 | 무엇이 잡는가 |
| --- | --- | --- | --- |
| `html.light` | — | 밝게 | 둘 다 안 맞습니다 |
| `html.dark` | — | 어둡게 | 앞: `.light` 조상이 없습니다 |
| `html.light` | `aside.dark` | 어둡게 | 뒤: `.light .dark *` |
| `html.dark` | `aside.light` | 밝게 | 앞을 `:not(.light *)` 가 걸러냅니다 |

`html.light` 가 필요한 이유는 `next-themes` 가 밝은 테마에서 그 클래스를 붙이기
때문입니다. 앱 안에서 `.dark` 를 «중첩»으로 쓰는 곳은 이 패널뿐이라
(전수 확인) 다른 화면은 영향이 없습니다.

### 검사가 거짓말할 뻔했습니다

대비를 재려고 `getComputedStyle` 의 색을 읽었더니 **전부 1.5:1** 이 나왔습니다.
색이 `lab()`·`oklab()` 으로 돌아오는데(원래 값이 `oklch()` 라서입니다) 그 숫자를
**RGB 인 척 읽었기** 때문입니다. 「대비가 다 나쁘다」는 결론이 그대로 나갈 뻔한
자리입니다 — 색 변환은 canvas 에 칠해 **브라우저에게 시킵니다.**

다시 재니 네 조합이 전부 맞았습니다.

| 앱 | 패널 | 본문 바탕 | 패널 바탕 |
| --- | --- | --- | --- |
| 밝음 | 어둠 | `rgb(255,255,255)` | `rgb(23,23,23)` |
| 밝음 | 밝음 | `rgb(255,255,255)` | `rgb(250,250,250)` |
| 어둠 | 어둠 | `rgb(10,10,10)` | `rgb(23,23,23)` |
| **어둠** | **밝음** | `rgb(10,10,10)` | `rgb(250,250,250)` |

말풍선 글씨는 밝은 패널에서 `rgb(54,65,83)` — `prose-invert` 가 **안 걸렸습니다.**
새로고침해도 고른 값이 남습니다. 스크린샷을 눈으로만 봤을 때는 밝은 화면을

### 아이콘만이 아니라 **읽어 주는 이름도** CSS 가 고릅니다

토글이 되려면 「지금 무엇인가」를 알아야 하는데, `resolvedTheme` 은 서버 렌더와
첫 렌더에서 `undefined` 입니다. 그것으로 그리면 하이드레이션이 어긋나고
**첫 페인트에 해가 달로 바뀌는 것이 눈에 보입니다.**

원래 코드가 아이콘을 `dark:` 변형으로 돌리고 있었던 이유가 그것이었고, 그
방식을 **이름에도** 적용했습니다 — `sr-only` 두 칸을 두고 어느 쪽이 보일지는
CSS 가 정합니다. lucide 아이콘은 스스로 `aria-hidden` 을 붙이므로
(`children` 도 a11y 속성도 없을 때) 이름은 그 두 칸에서만 나옵니다.
**`aria-label` 을 달면 그 둘을 덮어** 「테마 변경」이라는 뭉뚱그린 말만 남습니다.

누를 때는 이야기가 다릅니다 — 하이드레이션이 끝난 뒤라 `resolvedTheme` 을
그냥 읽습니다.

확인은 **읽어 주는 이름으로 단추를 찾아** 눌렀습니다(`getByRole`). 이름이
상태를 따라 안 바뀌면 그 자리에서 못 찾습니다 — 화면색만 봤으면 지나쳤을
검사입니다. 로그인 화면·서비스 화면 양쪽에서 라이트↔다크가 왕복했고,
**도우미 패널은 함께 바뀌지 않았습니다**(`DEC-067` 의 독립성).

### 폭: **변수 하나가 둘을 움직입니다**

패널의 폭(`md:w-[var(--chat-width)]`)과 본문 열이 밀리는 양
(`globals.css` 의 `padding-right`)이 **같은 `--chat-width`** 를 봅니다. 끌 때
고칠 것은 `<html>` 의 인라인 변수 하나뿐이고, 둘이 어긋날 자리가 없습니다 —
폭을 두 곳에 적었으면 끄는 동안 본문이 패널 밑으로 들어갔을 것입니다.
인라인이 스타일시트를 이기므로 `:root` 기본값도 1024px 규칙도 함께 덮습니다.

| 다룬 것 | 왜 |
| --- | --- |
| `setPointerCapture` | 안 잡으면 빨리 끌 때 커서가 손잡이를 앞질러 나가고 **그 순간 멈춥니다** |
| `html[data-chat-resizing]` | 끄는 동안 글자가 선택돼 화면 절반이 파랗게 칠해집니다 |
| 저장은 **놓을 때 한 번** | 움직일 때마다 쓰면 `localStorage` 에 초당 수십 번입니다 |
| `role="separator"` + 화살표 | 마우스 없이도 조절되어야 합니다. 패널이 오른쪽이라 **←가 넓히는 쪽** |
| `md` 부터만 | 좁은 화면에서는 패널이 화면을 통째로 덮으므로 조절할 것이 없습니다 |

### 「원한 폭」과 「지금 폭」은 다릅니다

한계는 720px 이되, 좁은 창에서는 **본문에 360px 를 먼저 남깁니다.** 그래서 창을
줄이면 폭이 함께 줄어야 하는데 — 그것만 하면 **한 번 좁아진 폭이 영영
그대로**입니다. 창을 도로 넓혀도 안 돌아옵니다.

사람이 «원한» 값을 따로 들고(`desiredRef`), 창이 바뀔 때마다 그것을 다시
재도록 했습니다. 실측: 700 → (창 900) 540 → (창 1100) **700** → (창 1440) 700.

데이터로 빼고** 실행을 이벤트 핸들러 한 곳(`run`)에 모았습니다 — ref 를

커밋 `3938e79` 「조건 없는 대량 삭제를 게이트에서 막는다 — **운영자의 메모를

그것입니다. 그리고 `check:delete` 게이트가 생겼습니다.

**그 게이트를 피해 갔습니다** — 코드가 아니라 `psql` 로 직접 지웠기 때문입니다.
게이트는 소스를 봅니다. SQL 은 못 봅니다.

프로젝트에는 휴지통이 있습니다(`FR-PROJ-004`). 앱으로 지웠으면 `deleted_at` 만

| --- | --- |

| 감사 로그 | **이름만** 남습니다. 생성 시 `diff` 를 안 남겨 설명·기간·상태가 없습니다 |
| 문서·할 일 | 감사 대상에서 **일부러 뺐습니다**(`[061]`) — 있었는지조차 알 수 없습니다 |

감사 로그를 「그릇만」으로 좁힌 판단이 여기서 대가를 치렀습니다. 그 판단
자체는 유지합니다(글쓰기를 감시하지 않는다) — 다만 **삭제된 것을 되살릴
근거가 없다**는 것을 알고 있어야 합니다.

### 답은 이미 저장소 안에 있었습니다

`tests/e2e/fixtures.ts` 가 이렇게 적어 두었습니다 — 「준비물은 **최소**로
만들고 반드시 치웁니다 … 남기면 다음 실행이 「이미 있다」로 시작합니다」.
그 파일은 검증 데이터에 **`e2e_` 접두사**를 붙이고 **그 접두사만** 지웁니다.

**이 세션 시작 때 읽은 파일입니다.** 읽고도 따르지 않았습니다.

### 규칙

1. **라이브 DB 에 `DELETE`·`UPDATE` 를 직접 돌리지 않는다.** 지울 일이 있으면
   앱의 삭제 경로(휴지통)를 쓴다
2. 검증 데이터는 **알아볼 수 있게** 만든다 — 이름에 접두사를 붙이고,
   정리는 **그 접두사로만** 한다
3. 정리 전에 **무엇을 지우는지 먼저 세어 본다.** `select` 로 대상을 확인하고
   그 목록이 전부 내 것인지 본다. 이번에 `select` 는 돌렸고 목록에 운영자의

`FR-ADM-004`·`FR-NOTI-001`·`FR-NOTI-002` 는 **가만히 뒀으면 초록**이었습니다 —
기능은 없어졌는데 **번호만 주석에 남아** 「구현됨」으로 세어지고 있었습니다.
`check-fr-coverage` 가 스스로 경고하는 함정입니다(*"안 만든 것의 번호를 주석에
적지 마십시오"*). 남은 동작이 실제로 가리키는 번호로 옮겼고, **설명하는
주석에도 없어진 번호를 안 적었습니다** — 적으면 그 자리가 다시 거짓 초록이
됩니다.

`--fixture` 로 닫힌 마일스톤의 고정본도 다시 찍었습니다. `FR-ADM-002~009` 같은
**범위 표기 안에 폐기 번호가 숨어** 있어 범위를 쪼개야 했습니다.

### E2E 를 지우지 않고 뒤집었습니다

| 전 | 후 |
| --- | --- |
| ① 가입 신청이 승인을 거쳐 대시보드까지 간다 | **가입하는 길이 없고, 로그인만이 유일한 입구다** |
| ④ 일반 회원은 관리 영역에 못 들어간다 | **세션 쿠키 속성 · 비로그인은 관리 영역에 못 들어간다** |

둘 다 주어를 잃었지만 **그 문이 닫혔다는 사실은 재 볼 값이 있습니다.**
지우기만 하면 아무 데서도 안 재게 됩니다.

④ 는 특히 **지우면 안 되는 것**이었습니다 — 그 시험이 세션 쿠키 속성
(`NFR-SEC-005`)도 함께 재고 있었고, `verify:sec` 이 「e2e 가 증명한다」고 그
시험에 기대고 있었습니다.

### 문지기가 하나로 줄었다 — 그래서 두 층으로 잽니다

관리 영역을 전에는 «역할»이 지켰고 지금은 **로그인 하나**입니다.

```
쿠키 없음   → location: /login?next=…   ← proxy 가 답함
죽은 쿠키   → location: /login          ← DAL 이 답함
```

`proxy` 는 쿠키의 **있음만** 봅니다. 아무 값이나 든 쿠키는 통과하고 거기서
막는 것은 `requireActiveUser()` 하나뿐입니다. 그래서 위층만 재면 **DAL 이
통째로 사라져도 초록**입니다. `location` 에 `next=` 가 붙었는지로 **누가
돌려보냈는지**를 가릅니다 — 「`/login` 으로 갔다」만 보면 두 경우가 구별되지
않아 **엉뚱한 이유로 초록**이 뜹니다.

### 딸려 온 것 — 「비공개」가 말과 다릅니다 (`OPEN-021`)

역할이 사라지며 `collection.service` 의 `PRIVATE` 판정이 함께 걷혔습니다.
논리는 맞습니다(이제 모두가 관리자다). 그런데 **화면에는 여전히 「비공개」라고
쓰여 있습니다.** 사람이 하나인 지금은 무해하고, 위험해지는 시점은
**에이전트가 각자 계정을 갖는 때**입니다.

### 조율에서 배운 것 — 그리고 지시받은 것

가입 제거와 역할 제거를 **두 에이전트에게 병렬로** 맡긴 것이 실책이었습니다.
둘 다 `User` 를 중심으로 도는 일이라 **나눌 경계가 애초에 없었습니다.** 같은
파일을 서로 덮어썼고, 소유권을 메시지로 조율하는 데 편집보다 많은 시간이
들었습니다. **메시지 왕복이 편집보다 느려서** — 「이 파일이 남았다」고 알리는
사이에 이미 정리돼 있고 「손대지 마세요」는 그 뒤에 도착했습니다. 제가 잰
숫자(타입 오류 99→136→111→0)가 계속 움직여 중간값을 여러 번 보고했습니다.

> **운영자 지시: 앞으로 서브에이전트에게 시키지 말고 직접 할 것.**

## [074] 2026-09-08 · Ingest API 도 URL 메타를 채운다 (OPEN-018 해소)

> 이어서 진행해

- **한 일:** `/api/ingest/resources` 가 `FETCH_URL_META` 를 걸게 함. `DEC-079`,
  `OPEN-018` 해소. 열린 항목 **1건**(`OPEN-019`)만 남음
- **이유:** 에이전트가 넣은 자료만 제목·요약이 비어 있었습니다

### 열어 보니 「핸들러가 없다」가 아니었습니다

`OPEN-018` 은 「`FETCH_URL_META` 는 이름만 있고 돌지 않는다」였는데, 열어 보니
**핸들러는 그 뒤에 이미 만들어져 있었습니다** — `server/jobs/url-meta` 가
Playwright 로 `og:*` 를 읽습니다. `jobs/index.ts` 에 `register` 도 돼 있고요.

**안 따라간 것은 Ingest 라우트 하나**였고, 그 자리 주석이 「핸들러가 아직
없습니다」라는 **낡은 사실을 계속 말하고** 있었습니다. 열린 항목이 오래 열려
있으면 그것을 설명하는 주석이 사실과 갈라집니다 — 항목을 닫는 사람이 주석까지
찾아가지 않기 때문입니다.

### 왜 이게 오늘 세션과 직결되나

**「경로는 둘이지만 로직은 하나」**(`DEV-08`)가 깨진 자리였습니다.

| | 화면 등록 | Ingest API |
| --- | --- | --- |
| GitHub | `FETCH_GITHUB_META` | `FETCH_GITHUB_META` |
| 그 밖 URL | `FETCH_URL_META` | **아무것도 안 검** |

헤르메스·오픈클로가 arXiv·문서 사이트·블로그를 밀어넣으면 **제목과 요약을
아무도 안 채웁니다.** 사람이 화면으로 넣은 것과 결과가 갈립니다.

조건도 화면 쪽과 같게 맞췄습니다 — 저장 결과가 아니라 **들어온 값**
(`parsed.data.url`)을 봅니다. `WriteResult` 에는 `url` 이 없어서 처음에
`result.url` 로 썼다가 타입 검사에 걸렸습니다.

### 실제로 밀어넣어 봤습니다

키를 발급해 에이전트가 하는 그대로 `POST /api/ingest/resources` 했습니다.

| URL | 결과 |
| --- | --- |
| `example.com` | `found:1 · title:"Example Domain" · filled:[]` |
| arXiv `1706.03762` | **`found:4 · filled:["summary","sourceName","authors"]`** |

앞엣것의 `filled:[]` 는 **설계대로**입니다 — 제목은 사람이 쓴 것을 절대 안 덮고,
그 페이지에는 `og:description` 이 없습니다. 뒤엣것에서 요약·출처·저자가 실제로
DB 에 들어간 것을 확인했습니다.

응답의 `queuedJobs` 도 이제 `["FETCH_URL_META"]` 를 말하고, **그 말이 참입니다** —
전에는 「돌지 않는 작업의 이름」이 될까 봐 일부러 비워 뒀던 자리입니다.

### 정리

확인용 자료 2건·작업 2건·API 키 1개를 전부 지웠습니다. `resources` 0 · `jobs` 0.

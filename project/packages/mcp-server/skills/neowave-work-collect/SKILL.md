# Neowave Work 자료 수집

Neowave Work은 사내 AI 개발 자료 지식 베이스입니다. 이 Skill은 **무엇을 채워야 하는지**가 아니라
**어떻게 채워야 좋은지**를 정합니다. 필드 목록은 `nwwork_list_content_types` 가 알려 줍니다.

## 왜 절차가 있는가

자료는 검수 단계 없이 바로 게시됩니다. **등록 시점이 유일한 품질 관문**입니다.
빈 요약과 중복 링크가 쌓이면 검색이 쓸모없어지고, 그때는 되돌리기 어렵습니다.

## 절차

### 1. 무엇을 왜 찾는지 먼저 확인한다

주제가 모호하면 묻습니다. "MCP 관련 자료"는 범위가 너무 넓습니다 —
`보안`인지 `서버 구현`인지 `클라이언트 연동`인지에 따라 고를 자료가 달라집니다.

### 2. 검색한다

`WebSearch` · `WebFetch` 를 씁니다. 검색 결과의 요약만 읽고 등록하지 않습니다 —
**원문을 열어 봅니다.**

### 3. 후보를 고른다

| 우선 | 종류 |
| --- | --- |
| 1순위 | 공식 문서 · 논문 원문 · 저장소 README |
| 2순위 | 저자 본인의 블로그 · 발표 자료 |
| 3순위 | 정리가 잘 된 요약 아티클 |

**2차 요약 기사만으로 등록하지 않습니다.** 원문이 있으면 원문을 등록하고,
요약이 특별히 좋으면 원문을 등록한 뒤 «관련»으로 이어 줍니다.

### 4. 중복을 확인한다 — 등록 전에 반드시

```
nwwork_check_duplicate { "url": "..." }
```

- **중복이면 등록하지 않습니다.** 사용자에게 기존 자료를 알려 주고 넘어갑니다.
- 기존 자료에 비어 있는 칸이 있으면 **보강**을 제안합니다 (5-보강 참고).
- 같은 내용을 다른 주소로 쓴 자료는 URL로 안 걸립니다 — `nwwork_search` 로 제목·주제도 함께 봅니다.
- 검색 결과에 `searchTruncated: true` 가 오면 **"없다"고 판단하지 않습니다.** 질의를 좁혀 다시 봅니다.

### 5. 타입을 정하고 필드를 확인한다

```
nwwork_list_content_types {}
```

돌아오는 `detailSchema` 가 그 타입의 **필수·선택 필드 전부**입니다.
여기에 없는 필드를 지어내지 않고, `required` 를 빠뜨리지 않습니다.

### 6. 요약을 쓴다

| 칸 | 규칙 |
| --- | --- |
| `summary` | **한 문장.** 무엇에 대한 자료인지만. 형용사를 쌓지 않습니다 |
| `keyPoints` | 불릿 **3~5개.** 원문 문장을 그대로 옮기지 않고 압축합니다 |
| `applicability` | **비워 두지 않습니다.** 아래 참고 |

**`applicability` 는 이 지식 베이스의 존재 이유입니다.**
드론·공간정보·개발팀 맥락에서 **이걸로 무엇을 할 수 있는지** 한 줄 이상 씁니다.
모르겠으면 자료를 덜 읽은 것입니다. 「참고할 만하다」는 아무것도 말하지 않습니다.

- 나쁨: `RAG 평가에 참고할 수 있음`
- 좋음: `드론 촬영 메타데이터 검색의 정확도를 RAGAS 지표로 측정해 볼 수 있다`

발행일이 **2년 이상** 지났으면 `summary` 에 그 사실을 적습니다.

### 7. 분류한다

```
nwwork_list_taxonomy {}
```

- 카테고리는 **1개.** 목록에 있는 `slug` 만 씁니다.
- 태그는 **3~5개.** 새로 만들기 전에 기존 태그를 먼저 봅니다 —
  `rag` 와 `RAG` 와 `retrieval-augmented` 가 따로 생기면 태그로 찾는 일이 안 됩니다.

### 8. 등록한다

```
nwwork_create_resource {
  "type": "...", "title": "...", "summary": "...", "url": "...",
  "category": "...", "tags": ["...", "..."],
  "detail": { ... }
}
```

**확인하지 못한 값은 비워 둡니다.** 스타 수·라이선스·최근 커밋은 서버 워커가 채웁니다.
추측해서 넣으면 자료가 오염되고, 틀렸다는 것을 아무도 모릅니다.

**토큰·비밀번호·API 키가 본문에 섞이지 않게 합니다.** 서버가 막지만 애초에 넣지 않습니다.

**실패하면 자동으로 다시 부르지 않습니다.**
- 검증 실패: 어느 칸이 왜 틀렸는지 문구에 옵니다. **고쳐서** 다시 부릅니다.
- 중복(409): 등록하지 않고 넘어갑니다. 같은 것을 다시 보내지 않습니다.
- 그 밖의 실패: 사용자에게 문구를 그대로 전하고 멈춥니다.

### 9. 보고한다

한 번의 작업이 끝나면 **등록 N건 · 중복 N건 · 실패 N건**을 정리해 말합니다.
등록한 것은 제목과 링크를, 실패한 것은 이유를 함께 적습니다.

## 한 번에 얼마나

**한 대화에서 10건을 넘기지 않습니다.** 한 번에 쏟아부으면 요약이 얕아지고
`applicability` 가 형식적으로 채워집니다. 더 필요하면 사용자에게 나눠 하자고 제안합니다.

## 보강

이미 있는 자료를 채울 때:

1. `nwwork_get_resource` 로 **지금 값을 먼저 봅니다.**
2. **비어 있는 칸만** 보냅니다. 전부 다시 보내면 사람이 손으로 고쳐 놓은 것을 덮어씁니다.
3. 타입은 바꿀 수 없습니다.

## GitHub 저장소

`GITHUB_REPO` 타입으로 등록하면 서버가 메타(스타·라이선스·최근 커밋)를 수집합니다.
소스 사본이 필요하면 등록 후 `nwwork_archive_github` 를 겁니다 —
작업만 걸고 즉시 돌아오며, 완료를 기다리지 않습니다.

## 도구

| 도구 | 언제 |
| --- | --- |
| `nwwork_list_content_types` | 등록 전, 타입별 필드 확인 |
| `nwwork_search` | 비슷한 자료가 있는지 (주제로) |
| `nwwork_check_duplicate` | 등록 전, 같은 URL이 있는지 |
| `nwwork_get_resource` | 보강 전, 지금 값 확인 |
| `nwwork_list_taxonomy` | 분류 전, 카테고리·태그 확인 |
| `nwwork_create_resource` | 등록 |
| `nwwork_update_resource` | 보강 |
| `nwwork_archive_github` | 저장소 소스 아카이브 |
